# InnoNetwork 7.0.0 Release Notes

Status: Draft (unreleased)
Release date: TBD

This draft describes work on the 7.0 line. It must not be used to create a
tag or a GitHub Release, and 6.1.1 remains the current published release.

## Scope

7.0.0 is a compatibility reset with one theme: one client, one configuration
type, one error type. It adds no product and no dependency. The source
migration is in [docs/Migration-7.0.0.md](../Migration-7.0.0.md); the error
model is specified in [docs/rfcs/error-model-7.0.md](../rfcs/error-model-7.0.md).

### Breaking changes

- `OperationNetworkClient` and `NetworkClientConfiguration` are removed.
  `start(_:replaySafety:deadline:)` is available on every `NetworkClient` and
  `EncodedRequestClient`, and `startUpload(_:replaySafety:deadline:)` on every
  `UploadNetworkClient`.
- `NetworkFailure` and `NetworkFailureKind` are removed.
  `NetworkOperation.value()` throws `NetworkError`; the payload-free value is
  `NetworkErrorSummary`.
- `NetworkError` gains `policyRejected(_:)` and `authentication(_:)`.
  `NetworkErrorCategory` gains `.policy` and `.authentication`, and
  `TimeoutReason` gains `.operationDeadline(_:)`.
- `ReachabilityReason` gains `.cellularDataUnavailable`, reported for
  `URLError.dataNotAllowed`, `.internationalRoamingOff` and `.callIsActive`,
  which were `.underlying`.
- `NetworkConfiguration.advanced(...)` starts from the `safeDefaults`
  baseline: a 30-second timeout, the protocol cache policy, and 256-event
  buffers. It keeps bypassing the `URLSession` cache when a response cache
  policy or a session refresh policy is configured.
- `DownloadError.maxRetriesExceeded` carries `lastError:`, and
  `DownloadError.unacceptableStatusCode(_:)` is added.
- `PersistentResponseCacheEvictionReason` gains `.bodyIntegrityMismatch`, and
  the persistent cache index format is version 5. A 6.x cache directory is
  reset on first open.

### Behavior changes

- A response over the body limit, an open circuit, and a full rate-limit or
  admission queue are never retried by the built-in policy and never counted
  by the circuit breaker.
- A session refresh that shows the session cannot be renewed is reported as
  `.authentication(.refreshFailed)` and is not retried. A refresh that failed
  on the network, timed out, or received a `408`, `429` or `5xx` keeps its own
  case and follows the ordinary retry rules. The proactive refresh of a request
  that has no token yet follows the same rule as the replay after a `401`.
- A named-credential provider whose own transport fails transiently reports
  that failure's secret-free classification instead of a credential failure,
  and the request is retried under the ordinary rules. Such a renewal failure
  does not use up the request's single renewal, and no failure while preparing
  a named credential counts against the request host's circuit breaker.
- `waitsForNetworkChanges` defers a retry only after a connectivity failure,
  for buffered requests, streaming handshakes and downloads, which share one
  connectivity table. `URLError.cannotConnectToHost` is a connection timeout,
  not a connectivity failure.
- A request or stream handshake that reaches transport with a credential
  header never has its response stored in `URLSession`'s cache, and under the
  protocol cache policy does not read it either, with either preset. Only an
  explicitly cache-first policy opts out.
- A `304` that cannot be reconciled with the stored response removes that
  entry before the error is reported, so a replay fetches a full response.
- Streaming handshakes replay once through the session refresh and take part
  in the circuit breaker.
- Downloads validate the HTTP status before staging the file, resume from
  resume data on automatic retry, and honor `pause(_:)` during a retry wait.
- A WebSocket connection that drops before
  `WebSocketReconnectPack.stabilityInterval` (default 10 s) continues the
  earlier reconnect budget instead of resetting it.
- The download persistence store replays its append log only when another
  writer changed it.
