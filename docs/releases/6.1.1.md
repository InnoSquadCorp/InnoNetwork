# InnoNetwork 6.1.1 Release Notes

Status: Ready
Release date: 2026-10-07 (intended; publication remains pending)

This source-compatible patch packages the library-owned AI agent skill and
post-publication documentation and publishing corrections. It does not change
runtime Swift implementation, public API, package dependency constraints, or
the root dependency lock relative to the published 6.1.0 release.

## Changes

- Add the library-owned `skills/innonetwork` source for Codex and Claude Code,
  with public-API examples, an independent consumer fixture, exact dependency
  provenance checks, and JSON/encoded request and lifecycle guidance.
- Declare support for stable 6.1.x. The retained fixture and its recorded
  thirteen-test evidence target exact 6.1.0; that historical evidence does not
  claim validation of every later patch. Consumers retain their resolved version
  and verify patch-specific behavior. Installing the Swift package does not
  install the AI skill; follow [the skill installation guide](../../skills/README.md).
- Correct the DocC publisher's canonical CI workflow recognition and narrowly
  permit the authenticated main aggregate's PR-metadata step to skip. Preserve
  exact-main evidence, artifact validation, and deployment safeguards.
- Reconcile 6.1.0 publication records and adoption documentation with the actual
  immutable tag and public Release, and clarify observability exporter examples.
- Unify GitHub Sponsors and Patreon links.

## Compatibility and scope

Swift 6.2+, the five Apple deployment floors, the nine runtime products and the
compiler-host support product are unchanged. There is no new migration step
relative to 6.1.0. SwiftSyntax 604.0.x and Swift Crypto 5.x graph requirements
remain those of 6.1.0. Optional companion packages have separate versions and
validation; this patch does not publish or certify them.

The existing 6.1.0 tag and release assets remain unchanged. Mock-transport and
library CI results do not establish live-service, device, background-transfer,
or application-specific acceptance.

## Validation and Ready decision

The authorized patch contents are Ready following the successful official
[non-publishing Release validation](https://github.com/InnoSquadCorp/InnoNetwork/actions/runs/37588410794)
on main `a8e7213d47f0925c05a7ff8b5803c16c28d75470`
(tree `e741056944542ecf86d26aa556fdee6d7651a590`). All seven validation jobs
passed, including the unchanged fifteen-gate full preflight and five-platform
matrix. Public-tag verification and publication were structurally skipped.

The [retained full-preflight evidence](https://github.com/InnoSquadCorp/InnoNetwork/actions/runs/37588410794/artifacts/11485424456)
records all fifteen gates passing and successful exact-main checks before and
after execution. Candidate consumers passed in release mode with default and
core-only traits at that exact revision. Their receipt explicitly states
`mode: candidate-revision`, `version: null`, and `public_tag_verified: false`.
This is candidate evidence, not a claim that the 6.1.1 tag already exists.

These Ready documentation edits require their own CI and normal integration.
The final Ready main must pass its own official non-publishing full preflight;
the intended date and active ruleset must be checked again before tagging.
Only then may the annotated current-main tag and tag-triggered public-consumer,
signing, and publication workflow run. Ready approves the contents and does
not assert a published 6.1.1 release. Existing 6.1.0 evidence and assets remain
immutable.
