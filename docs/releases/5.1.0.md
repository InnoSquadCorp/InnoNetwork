# InnoNetwork 5.1.0 Release Notes

Status: Ready for release

Release date: 2026-09-03

InnoNetwork 5.1 introduces four opt-in HLS companion products while keeping
the 5.0 compatibility baseline and the existing secure, macro-first network
client unchanged. Applications link only the streaming capabilities they use.

## New HLS products

- `InnoNetworkHLS` provides bounded HLS 2nd Edition playlist parsing,
  deterministic rendition selection, non-DRM AES-128 VOD assembly, resumable
  offline packages, Content Steering, interstitial metadata, and local
  playback sources.
- `InnoNetworkHLSLive` adds blocking and delta playlist reloads, LL-HLS
  freshness-aware tune-in, bounded health snapshots, and atomic live DVR with
  resumable checkpoints, rolling retention, rendition packaging, Date Range
  handling, and independently published time-shift snapshots.
- `InnoNetworkHLSAVFoundation` adds caller-owned playback configuration,
  bounded URL-free metrics and metadata, system-managed asset downloads,
  offline-asset inspection, integrated timelines, interstitial observation,
  and application-owned FairPlay streaming and persistent-key workflows.
- `InnoNetworkHLSAudio` is an Xcode 27 / Swift 6.4 companion for demand-driven
  decoded PCM, timebase-paced delivery, and optional full-mix processing on
  supported version 27 platforms. Xcode 26 retains an empty compatibility
  module so the rest of the package remains consumable.

## Safety and ownership boundaries

- Playlist, metadata, and event surfaces are bounded and `Sendable`; raw URLs,
  response bodies, native AVFoundation objects, license payloads, and key
  material do not cross diagnostic boundaries.
- HLS transport uses the package's typed request policy, URL admission,
  redirect handling, retry context, body limits, and value-redacted
  observability.
- FairPlay certificates, KSM authorization and transport, content-key storage,
  entitlement policy, and production acceptance remain application-owned.
- Download and DVR publication use destination-scoped exclusion, capacity
  reservations, durable checkpoints where enabled, and atomic final commits.

## Live and offline behavior

- LL-HLS state preserves key-format isolation across complete segments,
  partial segments, maps, and preload contexts; optional session-key and live
  key preloading stays bounded and falls back to the ordinary demand path.
- DVR packages preserve rotated fMP4 initialization maps, complete gaps,
  external audio and subtitle renditions, Date Range schedules, and typed
  retention or preload statistics.
- Offline packages retain typed rendition provenance and can be reopened as a
  local playback source. AVFoundation-managed `.movpkg` assets have separate
  inspection and reattachment APIs.

## Playback diagnostics

- Playback metrics cover startup requests, variant switches, buffer
  readiness, rate changes, bounded delivery loss, and health analysis without
  exposing media URLs.
- Timed metadata and integrated timeline monitors use independently
  cancellable bounded streams and retain caller ownership of players and
  presentation UI.
- Apple authoring diagnostics and presentation-graph inspection are analysis
  tools; they do not replace Apple's official HLS validators or real-device
  FairPlay acceptance.

## Compatibility and adoption

- The package continues to require Swift 6.2 and targets iOS 16, macOS 14,
  tvOS 16, watchOS 9, and visionOS 1. `InnoNetworkHLSAudio` has the narrower
  Xcode 27 / Swift 6.4 requirement described above.
- Existing 5.0 consumers do not need to change code. Add only the desired HLS
  product to the consuming target and keep the root package on the 5.x line:

```swift
.package(
    url: "https://github.com/InnoSquadCorp/InnoNetwork.git",
    .upToNextMajor(from: "5.1.0")
)
```

Use the product-specific DocC pages and README product-selection guide for
configuration examples. All HLS public declarations are Provisionally Stable
for the 5.x line; pin an exact or minor-bounded version when accepting only a
reviewed surface.

## Release validation

- SwiftPM tests run in serial coverage mode and bounded target shards.
- Xcode 26 and Xcode 27 package builds, all five Apple platform build tuples,
  consumer examples, DocC archives, public API ledgers, macro fixtures,
  ThreadSanitizer, CodeQL, coverage, and guarded benchmarks are required.
- The full local preflight additionally exercises AVPlayer runtime fixtures,
  decoded audio, full-mix processing, live DVR scenarios, and Apple's
  `mediastreamvalidator` plus `hlsreport` tools.

The isolated physical-device smoke verifies FairPlay session construction and
asset attachment contracts. A production KSM-backed encrypted playback and
persistent-key cycle still requires application credentials and protected
media, and is not claimed by this release.
