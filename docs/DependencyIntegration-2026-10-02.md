## Compatibility boundaries

The package still declares Swift tools 6.2, all nine library products, the
default Macros trait and the same deployment floors: iOS 16, macOS 14, tvOS 16,
watchOS 9 and visionOS 1. Runtime sources and public declarations are unchanged.
The macro contract now checks the intended 604.0.x patch-compatible range.
Negative controls still reject an out-of-range SwiftSyntax pin, now also reject
an out-of-range Crypto major, and retain the HTTP Types minimum-version check.

[Crypto 5.0](https://github.com/apple/swift-crypto/releases/tag/5.0.0) declares
Swift 6.2 and changes its cross-platform API to match newer CryptoKit. Its
manifest requirement alone does not establish compatibility with every Apple
SDK or deployment floor. [SwiftSyntax 604.0.0](https://github.com/swiftlang/swift-syntax/releases/tag/604.0.0)
likewise requires real macro expansion, diagnostics and consumer validation on
both supported compiler lanes.

The new 604.0.x constraint cannot be jointly resolved with a consumer dependency
that permits only 603.0.x. The existing 603-only multi-package integration
evidence is historical, not proof for this candidate. Disabling the Macros
trait removes compiled macro products but does not remove manifest dependency
resolution. Adopters with a 603-only macro dependency need a compatible upgrade
or a separately reviewed range strategy; this candidate does not silently
broaden the tested range.
